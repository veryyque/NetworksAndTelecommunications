# Лабораторная №4 · Змейка

Приложение для macOS 14 и новее показывает игры локальной сети и сервера курса, а также позволяет создать общую игру в локальной сети.

## Запуск

Откройте `Snake.xcodeproj`, выберите схему **Snakes** и устройство **My Mac**. Нажмите **⌘R** для запуска или **⌘U** для тестов. При первом открытии Xcode загрузит SwiftProtobuf 1.30.0.

Чтобы проверить сервер, введи имя игрока и новое имя игры, выбери **Создать игру → На сервере курса**. После появления поля нажми **Открыть веб-наблюдатель** и найди игру по этому имени. Пока смотришь, оставь приложение подключённым. Стрелки и WASD передают повороты на сервер. Для серверной игры размер поля, запас еды и интервал выбирает сервер.

Те же действия из терминала:

```sh
open Snake.xcodeproj
xcodebuild -project Snake.xcodeproj -scheme Snakes -destination 'platform=macOS' -derivedDataPath .build/xcode build
xcodebuild -project Snake.xcodeproj -scheme Snakes -destination 'platform=macOS' -derivedDataPath .build/xcode test
```

Для запуска трёх независимых экземпляров после сборки:

```sh
for i in 1 2 3; do open -n .build/xcode/Build/Products/Debug/Snakes.app; done
```

В первом экземпляре нажмите **Создать игру → В локальной сети**, задайте размер поля, запас еды и интервал. Во втором выберите игру и нажмите **Играть**, в третьем — **Смотреть**. Стрелки и WASD задают поворот на следующий ход. Переключение в просмотр удаляет змейку и сохраняет очки. Возвращение в игру запускает поиск свободного квадрата.

## Архитектура MVVM

- **Model** — `Sources/GameCore/Game.swift` хранит поле, игроков и очки, проверяет повороты и рассчитывает ход.
- **View** — `Sources/Snakes/Views/SessionView.swift` рисует поле и список игр, преобразует нажатия клавиш в направления и вызывает методы ViewModel.
- **ViewModel** — `Sources/Snakes/ViewModels/SessionViewModel.swift` хранит видимое состояние экрана, передаёт сетевые команды в `CourseSession`. Состояние экрана обновляется на `MainActor`.
- `CourseSession` и `CourseCatalog` отвечают за обмен с сервером, а `UDPTransport` — за датаграммы. `Sources/Snakes/App.swift` открывает окно с `SessionView`.


## Файлы

- Sources/GameCore/Game.swift содержит правила хода, размещения, подсчёта очков и изменения состава участников.
- Sources/Snakes/App.swift — точка входа в приложение.
- Sources/GameCore/UDP.swift открывает два неблокирующих сокета Darwin. Первый слушает общий multicast-порт. Второй получает собственный порт от ОС, отправляет анонсы через подходящие интерфейсы и обеспечивает индивидуальный адрес для ответов.
- Sources/GameCore/Reliability.swift содержит кеш ответов, очередь повторов, проверку порядка снимков и каталог с независимым сроком жизни записей.
- Protocol содержит оригинальный `snakes.proto` из ветки `master` курса, сгенерированные Swift-типы, проверку оболочки и тест предельного State. Для повторной генерации нужен `protoc`. Скрипт использует установленный `protoc-gen-swift` либо собирает версию 1.30.0 из GitHub.

```sh
./Scripts/generate.sh
```

Можно передать другой путь к оригинальной схеме первым аргументом скрипта.

## Как проходит сетевой ход

1. `SessionViewModel` передаёт направление в `CourseSession`. Участник отправляет `Steer` по UDP ведущему. У ведущего локальная команда сразу попадает в `LANHost`.
2. `LANHost` проверяет запрос и запоминает допустимый поворот; по таймеру считает ход и отправляет свежий `State` всем участникам.
3. Клиент проверяет отправителя и порядок снимка, восстанавливает поле и публикует его для SwiftUI на `MainActor`.

Игры обнаруживаются из двух источников. `LANHost` отправляет multicast-анонс на `239.192.0.4:9193` примерно раз в секунду. Каталог также запрашивает по unicast фиксированный сервер `snakes.ippolitov.me:9193`. Повторные объявления обновляют запись по паре «имя игры и endpoint ведущего». Для игр с этого Mac адреса его интерфейсов сводятся к loopback с сохранением игрового UDP-порта. Порт другого локального ведущего проверяется unicast-запросом Discover.

## Протокол для защиты

`msg_seq` идентифицирует сообщение отправителя. При повторе и в ACK номер сохраняется. `state_order` задаёт порядок снимков поля. Устаревший снимок подтверждается в пределах окна, но поле по нему не обновляется.

`DEPUTY` принимает снимки вместе с конфигурацией, адресами участников и `next_player_id`. При потере ведущего он удаляет старого `MASTER`, назначает заместителя и публикует более новый `State` с прежними очками. При штатном выходе старый ведущий сначала подтверждает доставку последнего снимка, затем посылает команду передачи роли.


## Проверка

- Прошли 7 тестов Xcode. Предельный снимок `State` сериализуется в 1145 байт при лимите 1200.
- Три отдельных процесса на одном Mac обнаружили игру по multicast, вошли игроком и наблюдателем, сменили статус и сохранили ненулевые очки при штатном выходе и принудительном завершении ведущего.
- Локальные UDP-проверки подтвердили, что пакет версии 1 игнорируется, повторный `Join` получает прежний ID при потере подтверждения, поздний запрос статуса не отменяет новый, а повторный `Leave` подтверждается после удаления игрока.
- Подключение к серверу курса проверялось в более ранней сборке. В текущей проверке новых игр на сервере курса не создавали. Совместимость с приложениями других студентов отдельно не проверялась.
